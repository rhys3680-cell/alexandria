# Alexandria

글과 음성을 알아서 정리하고, 찾아주고, 먼저 보여주는 개인용 데스크톱 앱.

적어 두거나 말해 둔 것을 그대로 던져 넣으면 제목·요약·태그·할 일·인물이 자동으로 붙고, 어떤 언어로 물어봐도 찾을 수 있게 색인됩니다. 정리는 사용자의 `claude` CLI가 백그라운드에서 수행하고, 음성 전사는 기기 안에서 whisper.cpp로 처리합니다.

## 설계 원칙

**보관소가 진실의 원천입니다.** 항목 하나가 마크다운 파일 하나입니다. SQLite는 파일에서 언제든 다시 만들 수 있는 파생 색인일 뿐이라, 색인이 깨져도 데이터 손실이 아닙니다. 파일은 다른 도구로도 읽히며, `claude` CLI를 보관소 폴더에 직접 붙여 쓸 수도 있습니다.

```
~/Alexandria/
  items/2026/08/20260812T0413-알렉산드리아-프로젝트-킥오프-회의-6APQFA.md
  media/01KZT2T68XKNV763TNG96APQFA.webm
  .alexandria/
    config.json
    index.db          ← 파생물. `alx reindex` 로 언제든 재생성
    vendor/           ← whisper.cpp 실행 파일과 모델
```

**네이티브 모듈이 0개입니다.** 색인은 Node/Electron에 내장된 `node:sqlite`를 쓰고, 음성 인식과 LLM 호출은 자식 프로세스로 실행합니다. Electron용 네이티브 모듈 재빌드가 없어 Windows에서 가장 흔한 빌드 실패 지점이 아예 사라집니다.

| 런타임 | SQLite | FTS5 | trigram | 확인 |
|---|---|---|---|---|
| Node 24.12 | 3.50.4 | ✓ | ✓ | 실측 |
| Electron 43 (Node 24.18) | 3.53.1 | ✓ | ✓ | 실측 |

**코어 하나를 CLI와 앱이 공유합니다.** `@alexandria/core`가 수집·전사·정리·색인 전부를 담당하고, CLI와 Electron 메인 프로세스가 같은 보관소를 엽니다. SQLite는 WAL 모드라 앱이 켜져 있는 동안 CLI로 넣은 항목을 앱의 백그라운드 워커가 그대로 집어갑니다. 폴더 감시는 앱이 아니라 `alx watch`가 담당합니다.

## 다국어 처리

정리 결과에서 제목·요약·태그·할 일·발췌는 **원문 언어 그대로** 두고, `keywords`만 항상 영어로 뽑습니다. 한국어 메모를 `kickoff meeting`으로 찾을 수 있는 이유입니다.

검색은 두 개의 FTS5 인덱스를 겹쳐 씁니다.

- `unicode61` — 띄어쓰기가 있는 언어(한국어, 영어 등)의 단어 단위 매칭
- `trigram` — 띄어쓰기가 없는 언어(일본어, 중국어)의 부분 문자열 매칭. 3자 이상 질의에서만 동작하며, 단어 인덱스가 부족할 때만 추가로 조회합니다.

## 먼저 보여주기

앱을 열면 목록이 아니라 **브리핑**이 먼저 뜹니다. 정리 단계에서 이미 뽑아 둔 `tasks`·`due`·`people`을 그대로 집계하므로 모델 호출이 없습니다 — 즉시 뜨고, 열 때마다 비용이 붙지 않습니다.

- **지났음 / 오늘 / 곧(기본 7일) / 언젠가** — 마감일 기준으로 나뉜 할 일. 체크박스로 완료 처리하면 원본 파일의 프론트매터에 기록되므로 재색인해도 남습니다.
- **오늘 끝냄** — 오늘 완료한 것. 되돌릴 수 있습니다.
- **그동안 정리됨** — 최근 48시간 안에 정리가 끝난 항목.
- **한 달 전 / 1년 전 오늘** — 그 날짜에 남긴 기록을 다시 꺼내 보여줍니다.
- **점검 필요** — 실패한 항목과 대기 중인 작업 수.

터미널에서도 같습니다. 인자 없이 `alx`만 치면 브리핑이 뜹니다.

```
$ alx
2026-08-12 수요일

오늘 (2)
  JS1HZ9·1  코드 서명 인증서 갱신 신청 넣기 2026-08-12
      ↳ 코드 서명 인증서 갱신 및 디자인 시안 회신

$ alx done JS1HZ9 1
완료  코드 서명 인증서 갱신 신청 넣기
```

## 비용

정리는 사용자의 `claude` CLI를 통해 실행되므로, **구독으로 로그인되어 있으면 별도 청구가 없고 구독 사용량 한도를 소모합니다.** `ANTHROPIC_API_KEY`로 동작 중이라면 그 금액이 실제로 청구됩니다. 앱과 `alx stats`가 보여주는 금액은 "API 요금제였다면 얼마였을지"의 환산치입니다.

호출당 비용은 어느 쪽이든 중요합니다 — 구독이라도 한도 소진 속도가 그만큼 달라지기 때문입니다. 이 기계에서 실측한 값:

| 호출 방식 | 입력 토큰 | 출력 토큰 | 환산 비용 |
|---|---|---|---|
| 기본 호출 (툴 스키마 포함) | 26,676 | 9 | $0.161 |
| `--disallowedTools` 로 나열 차단 | 11,781 | 9 | $0.0043 |
| **`--agents '{...,"tools":[]}'` + `--agent`** | **194** | 9 | **$0.0013** |
| 위 + `--effort low` (실제 정리 작업) | 329 | 255 | $0.0055 |
| 위와 동일하되 `--effort medium` | 329 | 635 | $0.0112 |

두 가지가 결정적이었습니다. 툴이 없는 에이전트를 선언하면 툴 스키마 전체가 요청에서 빠지고, 정리는 얕은 추출 작업이라 `--effort low`가 출력(=사고) 토큰을 절반으로 줄이면서 품질 저하 없이 오히려 코드펜스 없는 순수 JSON을 냅니다. 실제 메모 한 건 정리에 약 $0.009–0.015가 듭니다.

## 시작하기

```bash
pnpm install
pnpm build
```

`claude` CLI가 PATH에 있고 로그인되어 있어야 합니다. 점검:

```bash
pnpm alx doctor
```

음성을 쓰려면 whisper.cpp 실행 파일과 모델을 받습니다(Windows x64는 자동, 그 외 플랫폼은 빌드 안내가 출력됩니다). ffmpeg도 필요합니다.

```bash
pnpm alx setup whisper --model base
```

데스크톱 앱:

```bash
pnpm desktop
```

보관소 위치는 기본값이 `~/Alexandria`이고, `ALEXANDRIA_VAULT` 환경변수나 `--vault` 옵션으로 바꿉니다.

## CLI

```bash
alx                                                              # 브리핑 (= alx today)
alx done 6APQFA 1                                                # 할 일 완료 (--undo 로 되돌리기)
alx add "내일 3시 킥오프 회의, 벤치마크 정리해서 공유하기로 함"   # 수집만 (정리는 대기열로)
alx add --file recording.m4a --now                              # 수집 후 즉시 전사·정리
echo "긴 텍스트" | alx add                                       # 표준입력
alx watch ~/Downloads ~/Documents/notes                          # 폴더 감시 → 자동 수집·정리
alx run --follow                                                 # 대기열을 계속 처리
alx ls -n 20                                                     # 최근 항목
alx search "kickoff meeting"                                     # 교차 언어 검색
alx show 6APQFA                                                  # 상세 (뒤 6자리로 지정 가능)
alx stats                                                        # 현황과 누적 비용
alx reindex                                                      # 파일에서 색인 재생성
alx retry                                                        # 실패한 작업 재시도
alx config set llm.model haiku                                   # 설정 변경
```

## 처리 흐름

수집은 절대 실패하지 않도록 먼저 파일을 쓰고, 이후 작업은 큐로 넘깁니다.

```
captureText ──────────────────────────┐
                                      ├─→ organize ─→ organized
captureAudio ─→ transcribe ─→ ────────┘
```

- 작업은 SQLite 큐에 쌓이고 최대 3회까지 재시도합니다. 중간에 앱이 죽어도 `running` 상태로 남은 작업은 다음 시작 때 대기열로 되돌아갑니다.
- 정리가 끝나면 제목이 생기므로 그 시점에 파일명을 한 번 바꿉니다.
- 실패가 확정된 항목은 `failed` 상태와 원인이 파일에 남아 `alx retry`로 되살릴 수 있습니다.

## 구조

```
packages/core     수집·전사·정리·색인. Electron 의존성 없음
packages/cli      alx — 코어를 그대로 사용
apps/desktop      Electron + React. 메인 프로세스가 코어 인스턴스를 하나 소유
```

렌더러는 `contextBridge`로 노출된 좁은 API만 봅니다. DB 핸들도, 파일 경로도, Node도 렌더러로 넘어가지 않습니다.

## 테스트

```bash
pnpm test
```

빌드된 산출물을 대상으로 프론트매터 왕복, 파일명 정규화, FTS 질의 이스케이프, 교차 언어 검색, CJK trigram 검색, 큐 재시도, 그리고 모델을 스텁으로 바꾼 수집→정리 전체 경로를 검증합니다.
