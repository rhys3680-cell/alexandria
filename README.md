# Alexandria

[English](./README.en.md)

글과 음성을 알아서 정리하고, 찾아주고, 먼저 보여주는 개인용 데스크톱 앱.

적어 두거나 말해 둔 것을 그대로 던져 넣으면 제목·요약·태그·할 일·인물이 자동으로 붙고, 어떤 언어로 물어봐도 찾을 수 있게 색인됩니다. 정리는 사용자의 `claude` CLI가 백그라운드에서 수행하고, 음성 전사는 기기 안에서 whisper.cpp로 처리합니다.

## 설계 원칙

**보관소가 진실의 원천입니다.** 항목 하나가 마크다운 파일 하나입니다. SQLite는 파일에서 언제든 다시 만들 수 있는 파생 색인일 뿐이라, 색인이 깨져도 데이터 손실이 아닙니다. 파일은 다른 도구로도 읽히며, `claude` CLI를 보관소 폴더에 직접 붙여 쓸 수도 있습니다.

```
~/Alexandria/
  items/2026/08/20260812T0413-알렉산드리아-프로젝트-킥오프-회의-6APQFA.md
  media/01KZT2T68XKNV763TNG96APQFA.webm
  .alexandria/
    config.json
    index.db          ← 파생물. `alx reindex` 로 언제든 재생성
    vendor/           ← whisper.cpp 실행 파일과 모델
```

**재빌드가 필요한 네이티브 모듈이 없습니다.** 색인은 Node/Electron에 내장된 `node:sqlite`를 쓰고, 음성 인식과 LLM 호출은 자식 프로세스로 실행합니다. Windows에서 가장 흔한 빌드 실패 지점인 electron-rebuild가 아예 없습니다.

| 런타임 | SQLite | FTS5 | trigram | 확인 |
|---|---|---|---|---|
| Node 24.12 | 3.50.4 | ✓ | ✓ | 실측 |
| Electron 43 (Node 24.18) | 3.53.1 | ✓ | ✓ | 실측 |

유일한 예외는 의미 검색이 쓰는 `onnxruntime-node`인데, N-API 프리빌트라 두 런타임 모두에서 재빌드 없이 로드되는 것을 확인했습니다. 의미 검색을 켜지 않으면 로드조차 되지 않습니다.

**코어 하나를 CLI와 앱이 공유합니다.** `@alexandria/core`가 수집·전사·정리·색인 전부를 담당하고, CLI와 Electron 메인 프로세스가 같은 보관소를 엽니다. SQLite는 WAL 모드라 앱이 켜져 있는 동안 CLI로 넣은 항목을 앱의 백그라운드 워커가 그대로 집어갑니다. 폴더 감시는 앱이 아니라 `alx watch`가 담당합니다.

## 다국어 처리

정리 결과에서 제목·요약·태그·할 일·발췌는 **원문 언어 그대로** 두고, `keywords`만 항상 영어로 뽑습니다. 한국어 메모를 `kickoff meeting`으로 찾을 수 있는 이유입니다.

검색은 두 개의 FTS5 인덱스를 겹쳐 씁니다.

- `unicode61` — 띄어쓰기가 있는 언어(한국어, 영어 등)의 단어 단위 매칭
- `trigram` — 띄어쓰기가 없는 언어(일본어, 중국어)의 부분 문자열 매칭. 3자 이상 질의에서만 동작하며, 단어 인덱스가 부족할 때만 추가로 조회합니다.

## 음성

녹음하거나 오디오 파일을 넣으면 기기 안에서 전사한 뒤 같은 정리 파이프라인을 탑니다. 언어는 자동 감지합니다.

```bash
alx setup whisper --list        # 모델 비교
alx setup whisper               # 설치 (기본: small)
alx add --file 회의녹음.m4a --now
```

### 모델 선택

20초짜리 한국어 메모를 정답 대조로 측정했습니다.

| 모델 | 다운로드 | 오류 | 소요 |
|---|---|---|---|
| `base` | ~142 MB | 6개 (사람 이름·제품명 포함) | 18.1s |
| **`small`** (기본) | ~466 MB | 2개 | 42.9s |

**`base` 는 영어를 단어 단위로 정확히 받아쓰지만 한국어에서는 사람 이름을 틀립니다.** 틀린 이름은 그대로 항목의 `people` 필드에 들어가고, 그 뒤로는 아무도 잡아낼 수 없습니다. 느린 것보다 틀린 게 나쁘므로 기본값은 `small` 입니다. 영어만 다룬다면 `base` 로 충분합니다.

### 알아둘 한계

전사 오류는 정리 단계에서 **일부만** 복원됩니다. 같은 오디오를 두 모델로 돌렸을 때 한 번은 정리 단계가 `애패포` 를 `앱 배포` 로 되살렸고, 다른 한 번은 `에페포` 를 그대로 제목에 남겼습니다. 사람 이름처럼 중요한 항목은 `small` 이상에서 안정적이지만, 잘못 들린 일반 명사가 제목이나 태그에 남는 경우는 있습니다.

위 수치는 **TTS 로 만든 깨끗한 음성** 기준입니다. 실제 녹음은 잡음과 발화 습관 때문에 다를 수 있습니다.

## 의미 검색

어휘 검색만으로는 "그때 그 회의에서 정한 거"처럼 **표현이 다른** 질의를 못 찾습니다. 그래서 항목마다 로컬 임베딩을 만들어 두고, 검색할 때 어휘·의미 두 결과를 **순위로 융합(RRF)** 합니다. 원점수를 섞지 않는 이유는 bm25 와 코사인 유사도의 척도가 다르고, 임베딩 점수가 좁은 대역(정답 0.825 / 무관 0.790)에 몰려 있어 노이즈가 정답을 뒤집기 때문입니다.

기본은 꺼져 있습니다. 켜려면:

```bash
alx setup embeddings --list     # 고를 수 있는 모델
alx setup embeddings            # 내려받고 켜기 + 기존 항목 백필
alx search "데이터베이스를 UI 에서 떼어놓은 이유"
```

결과마다 어느 색인이 찾았는지(`어휘` / `의미` / `둘다`) 표시됩니다. 모델이 없거나 실패하면 조용히 어휘 검색으로 내려가므로, 이 기능을 켜지 않아도 앱은 그대로 동작합니다. 임베딩은 전부 기기 안에서 계산되어 **비용이 들지 않고 데이터도 나가지 않습니다.**

### 모델 선택

한국어·일본어·영어를 섞은 항목 5개에 질의 10개로 측정했습니다. **표본이 작으므로 방향성으로만 읽으십시오** — 문서 5개에서 만점은 나오기 쉽습니다.

| 모델 | 다운로드 | 차원 | rank1 | MRR |
|---|---|---|---|---|
| `multilingual-e5-small` | ~60 MB | 384 | 4/10 | 0.633 |
| **`multilingual-e5-base`** (기본) | ~110 MB | 768 | 7/10 | 0.783 |
| `bge-m3` | ~570 MB | 1024 | 10/10 | 1.000 |

실패는 한 방향으로 일관됩니다: **한국어 질의가 비한국어 노트에 닿지 못합니다.** 영어 질의로 한국어 노트를 찾는 것은 e5-base 에서 잘 되지만 그 반대는 약합니다. 교차 언어 검색이 중요하다면 `alx setup embeddings -m Xenova/bge-m3` 로 바꾸십시오. 모델을 바꾸면 기존 벡터는 무시되고 자동으로 다시 임베딩합니다.

## 관련 기록

항목을 열면 이어지는 과거 기록을 함께 보여줍니다. 두 개의 독립적인 신호를 씁니다.

- **공유 facet** — 태그·키워드·인물이 겹치는 항목. 정확하고, 무엇보다 **왜 관련 있는지 말할 수 있습니다**
- **의미 이웃** — 아무도 태그하지 않은 연결을 잡습니다 (의미 검색이 켜져 있을 때)

```
$ alx related 6APQFA
알렉산드리아 프로젝트 킥오프 회의 와(과) 이어지는 기록

  둘다 9SFKK2  STT 벤치마크 중간 결과 공유
      ↳ 공유: STT, base model, 김지훈
  공유 PH3M5V  Whisper base 모델 회의 녹음 전사 테스트
      ↳ 공유: whisper, base model, medium model
```

### 관련 없으면 아무것도 보여주지 않습니다

이 기능의 핵심은 **하한선**입니다. 유사도 상위 N개를 그냥 보여주면 보관소 전체가 "관련"으로 나오고, 사용자는 이 영역을 무시하게 됩니다.

절대 임계값은 쓸 수 없다는 것을 측정으로 확인했습니다. 서로 **무관한** 노트 5개의 모든 쌍이 0.739–0.815 안에 몰렸고, 최상위 쌍조차 공통점이 없는 조합이었습니다. 임베딩 공간이 비등방성이라 무엇도 무엇에서 멀지 않습니다. 평균 중심화는 분산을 넓혔지만 순위는 고치지 못했습니다 — 복원할 신호 자체가 없었기 때문입니다.

그래서 판정은 **항목별 자기 기준선 대비**로 합니다. 그 항목이 보관소 전반과 얼마나 비슷한지를 먼저 재고, 거기서 뚜렷하게 튀는 것만 관련으로 인정합니다. 모델이 무엇이든 자동으로 맞춰지고, 맞는 게 없으면 아무것도 반환하지 않습니다. 실제로 Electron 설계 노트는 "관련 기록 없음"이 나옵니다.

## 먼저 보여주기

앱을 열면 목록이 아니라 **브리핑**이 먼저 뜹니다. 정리 단계에서 이미 뽑아 둔 `tasks`·`due`·`people`을 그대로 집계하므로 모델 호출이 없습니다 — 즉시 뜨고, 열 때마다 비용이 붙지 않습니다.

- **지났음 / 오늘 / 곧(기본 7일) / 언젠가** — 마감일 기준으로 나뉜 할 일. 체크박스로 완료 처리하면 원본 파일의 프론트매터에 기록되므로 재색인해도 남습니다.
- **오늘 끝냄** — 오늘 완료한 것. 되돌릴 수 있습니다.
- **그동안 정리됨** — 최근 48시간 안에 정리가 끝난 항목.
- **한 달 전 / 1년 전 오늘** — 그 날짜에 남긴 기록을 다시 꺼내 보여줍니다.
- **점검 필요** — 실패한 항목과 대기 중인 작업 수.

터미널에서도 같습니다. 인자 없이 `alx`만 치면 브리핑이 뜹니다.

```
$ alx
2026-08-12 수요일

오늘 (2)
  JS1HZ9·1  코드 서명 인증서 갱신 신청 넣기 2026-08-12
      ↳ 코드 서명 인증서 갱신 및 디자인 시안 회신

$ alx done JS1HZ9 1
완료  코드 서명 인증서 갱신 신청 넣기
```

## 비용

정리는 사용자의 `claude` CLI를 통해 실행되므로, **구독으로 로그인되어 있으면 별도 청구가 없고 구독 사용량 한도를 소모합니다.** `ANTHROPIC_API_KEY`로 동작 중이라면 그 금액이 실제로 청구됩니다. 앱과 `alx stats`가 보여주는 금액은 "API 요금제였다면 얼마였을지"의 환산치입니다.

호출당 비용은 어느 쪽이든 중요합니다 — 구독이라도 한도 소진 속도가 그만큼 달라지기 때문입니다. 이 기계에서 실측한 값:

| 호출 방식 | 입력 토큰 | 출력 토큰 | 환산 비용 |
|---|---|---|---|
| 기본 호출 (툴 스키마 포함) | 26,676 | 9 | $0.161 |
| `--disallowedTools` 로 나열 차단 | 11,781 | 9 | $0.0043 |
| **`--agents '{...,"tools":[]}'` + `--agent`** | **194** | 9 | **$0.0013** |
| 위 + `--effort low` (실제 정리 작업) | 329 | 255 | $0.0055 |
| 위와 동일하되 `--effort medium` | 329 | 635 | $0.0112 |

두 가지가 결정적이었습니다. 툴이 없는 에이전트를 선언하면 툴 스키마 전체가 요청에서 빠지고, 정리는 얕은 추출 작업이라 `--effort low`가 출력(=사고) 토큰을 절반으로 줄이면서 품질 저하 없이 오히려 코드펜스 없는 순수 JSON을 냅니다. 실제 메모 한 건 정리에 약 $0.009–0.015가 듭니다.

## 시작하기

```bash
pnpm install
pnpm build
```

`claude` CLI가 PATH에 있고 로그인되어 있어야 합니다. 점검:

```bash
pnpm alx doctor
```

음성을 쓰려면 whisper.cpp 실행 파일과 모델을 받습니다(Windows x64는 자동, 그 외 플랫폼은 빌드 안내가 출력됩니다). ffmpeg도 필요합니다.

```bash
pnpm alx setup whisper
```

데스크톱 앱:

```bash
pnpm desktop
```

보관소 위치는 기본값이 `~/Alexandria`이고, `ALEXANDRIA_VAULT` 환경변수나 `--vault` 옵션으로 바꿉니다.

## 설치본 만들기

```bash
pnpm --filter @alexandria/desktop package
```

`apps/desktop/release/` 에 NSIS 설치 파일이 생깁니다.

패키징에서 실제로 문제가 됐던 것들:

- **pnpm 레이아웃** — electron-builder 는 프로덕션 의존성 트리를 걸어야 무엇을 넣을지 정하는데, pnpm 의 기본 심볼릭 레이아웃에서는 패키지의 의존성이 패키지 안이 아니라 스토어의 형제 위치에 있습니다. 그 결과 devDependency 까지 통째로 담아 `app.asar` 이 **695 MB** 가 됐습니다. `pnpm-workspace.yaml` 의 `nodeLinker: hoisted` 로 해결합니다.
- **명시적 허용목록** — 자동 수집에 맡기지 않고, 메인 번들이 external 로 둔 세 모듈(`@huggingface/transformers`, `onnxruntime-node`, `sharp`)의 런타임 폐포를 `electron-builder.yml` 에 직접 적었습니다. 빠뜨리면 `Cannot find module 'detect-libc'` 처럼 **즉시 시끄럽게** 실패하는데, 이는 워크스페이스를 통째로 담는 조용한 실패보다 낫습니다.
- **`.node` 는 asar 밖으로** — `dlopen` 은 디스크상의 실제 경로를 요구하므로 `asarUnpack` 이 필요합니다.
- **플랫폼별 바이너리** — `onnxruntime-node` 는 지원 플랫폼 전부의 프리빌트를 담고 있어(210 MB) 현재 타깃만 남깁니다. 브라우저 전용인 `onnxruntime-web`(128 MB)도 제외했고, 그 상태로 임베딩이 도는 것을 확인했습니다.

결과: 압축 해제 기준 **1,216 MB → 438 MB**, `app.asar` 은 695 MB → 12 MB.

> **Windows 참고** — 갓 추출된 디렉터리의 이름 변경이 `EPERM` 으로 실패하는 경우가 있습니다. 추출 프로세스가 핸들을 놓기 전에 electron-builder 가 rename 을 시도해서 생기는 경합이고, 그대로 다시 실행하면 통과합니다.

## CLI

```bash
alx                                                              # 브리핑 (= alx today)
alx done 6APQFA 1                                                # 할 일 완료 (--undo 로 되돌리기)
alx add "내일 3시 킥오프 회의, 벤치마크 정리해서 공유하기로 함"   # 수집만 (정리는 대기열로)
alx add --file recording.m4a --now                              # 수집 후 즉시 전사·정리
echo "긴 텍스트" | alx add                                       # 표준입력
alx watch ~/Downloads ~/Documents/notes                          # 폴더 감시 → 자동 수집·정리
alx run --follow                                                 # 대기열을 계속 처리
alx ls -n 20                                                     # 최근 항목
alx search "kickoff meeting"                                     # 어휘+의미 융합 검색
alx setup embeddings                                             # 의미 검색 켜기
alx embed                                                        # 임베딩 없는 항목 채우기
alx show 6APQFA                                                  # 상세 (뒤 6자리로 지정 가능)
alx related 6APQFA                                               # 이어지는 과거 기록
alx stats                                                        # 현황과 누적 비용
alx reindex                                                      # 파일에서 색인 재생성
alx retry                                                        # 실패한 작업 재시도
alx config set llm.model haiku                                   # 설정 변경
```

## 처리 흐름

수집은 절대 실패하지 않도록 먼저 파일을 쓰고, 이후 작업은 큐로 넘깁니다.

```
captureText ──────────────────────────┐
                                      ├─→ organize ─→ organized
captureAudio ─→ transcribe ─→ ────────┘
```

- 작업은 SQLite 큐에 쌓이고 최대 3회까지 재시도합니다. 중간에 앱이 죽어도 `running` 상태로 남은 작업은 다음 시작 때 대기열로 되돌아갑니다.
- 정리가 끝나면 제목이 생기므로 그 시점에 파일명을 한 번 바꿉니다.
- 실패가 확정된 항목은 `failed` 상태와 원인이 파일에 남아 `alx retry`로 되살릴 수 있습니다.
